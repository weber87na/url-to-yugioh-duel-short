# 工程與時間軸

## 環境與來源

以獨立工作目錄保存 `source/`、`analysis/`、`assets/`、`audio/`、`scripts/`、`qa/`、`output/`，不在 skill 安裝目錄生成影片。先確認 Python、FFmpeg、FFprobe、yt-dlp 和現有轉錄工具；Windows 可用 `python -X utf8` 避免中日文輸出編碼錯誤。

網址來源用可用下載工具取得單支影片及 info JSON／字幕；來源查找優先原始節目、官方片段和官方曲目。音訊連結失效不等於可用，必須實際取得並 probe。外部原音與卡圖保存 URL、標題／版本、來源秒數和檔案雜湊，不把搜尋摘要當作已核對原音。

先擷取代表幀與帶時間碼字幕。逐字稿用來找候選句，人物畫面、嘴形、硬字幕和聲音用來核對講者；鏡頭對著某人不代表聲音就是他。聽不到原音時如實記錄使用了哪些驗證，不把波形或 ASR 說成人工聽辨。

字幕和事件分開管理：

- `source_start/end` 是原片時間；`start/end` 是成片時間。
- 一段語音的映射是 `output_start + (source_time - source_start)`，預設原速。
- 每段聲音保留完整關鍵字／句尾；刻意靜默明列時間。
- 語音字幕只能顯示原文；遊戲解說如「僅剩 1 HP」放在敘事層。
- 跨事件拼接或歷史畫面插入標明戲仿／資料畫面，不偽造當時因果。

燒錄字幕和 SRT 共用一份已校對 cue 清單，包含成片 `start/end`、`speaker`、`text`。若舊工程同時有 `captions` 與 `subtitle_cues`，先指定權威來源，核對數量與時間後再供 renderer 使用，避免新增原音卻漏掉字幕。新版預設只在發聲期間顯示場內字幕條；無台詞時不留空面板，遊戲敘事另用事件提示。

## 工程範本

複製 [duel-project.example.json](../assets/duel-project.example.json)，補入本案資料。它記錄設計與時間軸，**沒有附一鍵渲染引擎**；新 renderer 應消費這些欄位，既有 renderer 可用明確轉換對接。

重要欄位：

| 欄位 | 用途 |
| --- | --- |
| `status` | 草稿用 `draft`；來源／素材／時間軸核對完才轉 `ready_to_render` |
| `format` | 成片尺寸、fps、像素場景邏輯尺寸 |
| `layout` | 明列座標單位、場地、緊湊資訊列、臨時字幕、角色位置及卡牌特寫寬度 |
| `characters` | id、朝向、動作圖、`standing_height_px`、`pose_meta`；同一人物所有動作沿用站姿比例 |
| `cards` | id、卡名、卡種／子類型、屬性、適用數值、`description`、正背圖、來源／提示詞 |
| `sources`、`voice_clips` | 原片、講者、剪點、成片位置、查核狀態 |
| `events` | phase、start/end、actor、target、card、impact_at、HP 等 |
| `audio_stems` | dialogue／effects／music 分離檔案 |

缺圖或缺原音的欄位用 null，不能暗中用占位圖完成正式 render。事件必須落在總片長內；效果與 HP 在命中點改變，持續效果則明列起訖。多角色／怪獸以 id 和持有者區分，不把「場上右側」誤當怪獸所有權。

`layout` 的座標是已驗收版面的起點，可隨人物和字幕調整。卡片效果資料與卡面 `description` 要一致：修改傷害、回手條件或移除對象時，同步更新顯示文案與事件數據。未實作的卡種／屬性應明確擴充素材和分支，不能默認全部畫成通常魔法或暗屬性怪獸。

## 節奏與視覺敘事

`intro / field / opponent_play / hit / crisis / hand / draw / reveal / activate / effect / victory` 是可選階段，不固定每階段幾秒。

- 手牌展示讓每張卡的圖和名字可辨；有對應原音時按說出卡名順序高亮。
- 神抽：停頓或低音量→抽牌動作→卡背滑出→翻面亮牌→發動。不要直接把卡面貼上去叫作抽牌。
- 卡片效果必須改變場面：召喚出怪、陷阱束縛、場地變海、目標受擊／跳躍等。
- 人物需要準備／動作／結果至少能辨識的姿勢。跳海實例是屈身→起跳→空中→入水；新卡效果用相應動作。
- 勝負要有結果停留，不在原音末字或觀眾尚未看清時切黑。

卡牌戰可用戲仿規則，只要敘事清楚；不要要求使用者的笑點完全符合競技遊戲王規則。

## 最小驗收

先看全場、兩張手牌、神抽、發動和最容易裁手的姿勢等代表幀；動作要用短片看連續性。正式輸出後再從實際 MP4 抽查，不能只驗未編碼圖片。

1. ffprobe 核對尺寸、fps、實際幀數、音軌、時長；以 `ffmpeg -v error -i final.mp4 -f null -` 完整解碼。
2. 核對所有指定金句、講者、字幕時序與句尾；原音較配樂清楚。記錄音訊峰值，無可聞／數值削波。
3. 查卡名、卡種框、屬性／星數及適用欄位是否正確，效果文字是否清楚，所有可辨識卡背是否一致，HP 是否在命中點更新。
4. 查每種動作的手臂／手指／腳／道具、倒地姿勢及旋轉後卡面外框；確認無外來殘肢、邊界裁切、比例跳動，字幕與提示未蓋住需辨識的臉或卡名，下方 HP 保有間距。
5. 只改音樂時驗視訊雜湊一致；只改畫面且聲音無改動時，優先直接複製已驗證音軌並比對音訊資料雜湊。仍需重混時沿用原音剪點和分軌，不重新猜測語句。
6. 版面改版以工程差異核對卡效果、原音剪點、字幕及 HP 命中點；更新 `picture_source`、`picture_project`、renderer 和封裝說明，不把新渲染畫面誤記為舊版視訊複製。

保留最終 MP4、SRT、工程、原音剪點、素材及提示詞、來源／混音紀錄。驗收範圍如實描述，不把抽樣檢查稱為逐幀人工審片。
